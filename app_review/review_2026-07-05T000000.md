### 💡 LOW RISK (Nice to Have)

#### Issue #1: `--only` substring filter could over-select in edge cases

**Description**: `_default_transcribe` passes `video.stem` to `transcribe.py --only`, which performs a substring match (`args.only.lower() in p.name.lower()`). If two files share a common stem prefix (e.g., `A.mkv` and `AB.mkv`), passing `--only A` would match both. This is an existing behavior of `transcribe.py`, not introduced by this chunk.

**Location**:
- File: `transcribe/ingest_new.py`
- Lines: `52-56`

**Offending Code**:
```python
def _default_transcribe(video: Path, transcripts_dir: Path) -> None:
    subprocess.run(
        [sys.executable, str(Path(__file__).resolve().parent / "transcribe.py"),
         str(video.parent), "--only", video.stem, "--out", str(transcripts_dir)],
        check=True,
    )
```

**Recommended Solutions**:
1. **Accept as-is** (Preferred)
   - The Masterclass files have sufficiently unique names (e.g., "Masterclass 01", "Masterclass 02") that substring collisions are practically impossible.
   - Even if a collision occurred, `transcribe.py` skips already-transcribed files (line 74), so the worst case is a redundant no-op pass, not data corruption.
   - Fixing this would require modifying `transcribe.py` to add an `--exact` flag, which is out of scope for chunk 24.
