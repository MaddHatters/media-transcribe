#### Issue #2: `detect_player()` accepts unused `timeout` parameter

**Description**: The function signature declares `timeout: float = 30.0` but the body never references it. The plan specifies "Polls with configurable timeout (like obs_capture.py's 30s wait)" — the polling loop was not implemented.

**Location**:
- File: `src/players/detector.py`
- Lines: `54-66`

**Offending Code**:
```python
async def detect_player(cdp, timeout: float = 30.0):
    raw = await cdp.js(DETECTION_JS)  # single attempt, no polling
    if not raw:
        return DetectionResult(player=None, element=None, meta={}), None
    # ...
```

**Recommended Solutions**:
1. **Implement polling with timeout** (Preferred)
   - Wrap the JS eval in a loop that retries until a player is found or `timeout` seconds elapse. This matches the plan's intent and `obs_capture.py`'s 30s wait pattern.
   ```python
   import asyncio, time
   deadline = time.monotonic() + timeout
   while time.monotonic() < deadline:
       raw = await cdp.js(DETECTION_JS)
       if raw and json.loads(raw).get("player"):
           break
       await asyncio.sleep(1.0)
   ```

2. **Remove the parameter if polling isn't needed**
   - If single-shot detection is the intended design, remove `timeout` to avoid confusion.
   - Trade-off: Loses the ability to wait for lazy-loaded players.

#### Issue #3: `VimeoPlayer.play()` SDK injection race condition

**Description**: `play()` injects the Vimeo SDK script tag in one `cdp.js()` call, then immediately calls `new Vimeo.Player(iframe)` in the next. The `<script>` tag loads asynchronously — `Vimeo` may not be defined yet when the second eval runs. The existing `obs_capture.py` code (via Playwright's `add_script_tag`) waits for the script to load before continuing.

**Location**:
- File: `src/players/vimeo.py`
- Lines: `11-29`

**Offending Code**:
```python
async def play(self, cdp, detection) -> None:
    await cdp.js(
        "(function() {"
        "  if (!document.querySelector('script[src*=\"vimeo\"]')) {"
        "    var s = document.createElement('script');"
        f"    s.src = '{VIMEO_SDK_URL}';"
        "    document.head.appendChild(s);"
        "  }"
        "})()"
    )
    # No wait for script load — Vimeo may not be defined yet
    await cdp.js(
        "(function() {"
        "  const iframe = document.querySelector(\"iframe[src*='vimeo']\");"
        "  window.__p = new Vimeo.Player(iframe);"  # may throw ReferenceError
        # ...
    )
```

**Recommended Solutions**:
1. **Wait for SDK load with a Promise** (Preferred)
   - Combine injection and initialization into one eval that awaits the load event:
   ```python
   await cdp.js(
       "(async function() {"
       "  if (typeof Vimeo === 'undefined') {"
       "    await new Promise(resolve => {"
       "      var s = document.createElement('script');"
       f"      s.src = '{VIMEO_SDK_URL}';"
       "      s.onload = resolve;"
       "      document.head.appendChild(s);"
       "    });"
       "  }"
       "  const iframe = document.querySelector(\"iframe[src*='vimeo']\");"
       "  window.__p = new Vimeo.Player(iframe);"
       "  window.__ended = false;"
       "  window.__p.on('ended', () => { window.__ended = true; });"
       "})()"
   )
   ```
   - Since `CDPClient.js()` already passes `awaitPromise: true`, this will work correctly.

2. **Add a polling wait between the two calls**
   - Insert `await asyncio.sleep(2)` between SDK injection and Player creation.
   - Trade-off: Fragile timing; the Promise approach is more reliable.
