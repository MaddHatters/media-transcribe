#### Issue #1: TransferClient subprocess calls don't catch TimeoutExpired

**Description**: The `upload()`, `download()`, and `_ssh_run()` methods in `TransferClient` pass `timeout=` to `subprocess.run()` but don't catch `subprocess.TimeoutExpired`. If SSH/SCP hangs (common with network issues), the exception propagates uncaught through the pipeline. By contrast, `src/analyze/quality.py` and `src/analyze/frames.py` both wrap their subprocess calls in try/except for `TimeoutExpired` — this module should follow the same pattern.

**Location**:
- File: `src/transfer/sync.py`
- Lines: `18-42`

**Offending Code**:
```python
def _ssh_run(self, command: str, timeout: int = 30) -> subprocess.CompletedProcess:
    return subprocess.run(
        ["ssh", *self._ssh_opts, self._host, command],
        capture_output=True, text=True, timeout=timeout,
    )

def upload(self, local: Path, remote: str) -> bool:
    result = subprocess.run(
        ["scp", *self._ssh_opts, str(local), f"{self._host}:{remote}"],
        capture_output=True, text=True, timeout=120,
    )
```

**Recommended Solutions**:
1. **Wrap each subprocess.run in try/except TimeoutExpired** (Preferred)
   - Return a synthetic `CompletedProcess(returncode=-1)` on timeout, matching the pattern in `quality.py:_run_cmd` and `frames.py:_run_cmd`.
   - For `upload()` and `download()`, the existing `returncode != 0` checks will then handle the failure gracefully.
   - For `_ssh_run()`, callers already check `returncode != 0`.
   - Rationale: Consistent with the codebase's established pattern and the AGENTS.md guideline ("never silently swallow errors").

#### Issue #2: cli.py extract-frames assumes .srt→.mp4 filename mapping

**Description**: The `extract-frames` CLI command maps gap filenames to video files by replacing `.srt` with `.mp4`. Videos could be `.mkv`, `.webm`, `.mov`, or other formats. If the recording is not `.mp4`, the frame extraction silently skips it (the `if video_path.exists()` guard prevents errors, but no frames are extracted).

**Location**:
- File: `cli.py`
- Lines: `153`

**Offending Code**:
```python
video_file = gap.get("file", "").replace(".srt", ".mp4")
video_path = videos_dir / video_file
if video_path.exists():
```

**Recommended Solutions**:
1. **Search for matching video by stem across all known extensions** (Preferred)
   - Use the `VIDEO_EXTS` set from `whisper_runner.py` to find a matching video file by stem.
   - ```python
     from src.transcribe.whisper_runner import VIDEO_EXTS
     stem = Path(gap.get("file", "")).stem
     candidates = [videos_dir / f"{stem}{ext}" for ext in VIDEO_EXTS]
     video_path = next((c for c in candidates if c.exists()), None)
     if video_path:
     ```
   - Rationale: The project records in `.mkv` format via OBS, making `.mp4`-only a known miss.

2. **Add a `--video-ext` CLI flag** (Alternative)
   - Let the user specify the video extension: `--video-ext mkv`.
   - Trade-off: Simpler implementation but requires user to know the extension upfront.

#### Issue #3: Pipeline _step_analyze discards QualityReport

**Description**: The `_step_analyze` method runs `QualityAnalyzer.analyze()` but only logs a warning if the verdict is `re_record`. The `QualityReport` object (verdict, trim points, detected issues) is not stored anywhere — downstream steps and the final `PipelineResult` have no access to the quality analysis results.

**Location**:
- File: `src/pipeline/runner.py`
- Lines: `102-111`

**Offending Code**:
```python
async def _step_analyze(self, post, result: PipelineResult) -> None:
    from src.analyze.quality import QualityAnalyzer
    recording = result.output_paths.get("recording")
    if not recording:
        log.warning("No recording path — skipping analyze")
        return
    analyzer = QualityAnalyzer()
    report = analyzer.analyze(Path(recording))
    if report.verdict == "re_record":
        log.warning("Quality verdict: RE_RECORD for %s", post.title)
```

**Recommended Solutions**:
1. **Store key report fields in `output_paths`** (Preferred)
   - Add `result.output_paths["quality_verdict"] = report.verdict` and `result.output_paths["quality_notes"] = report.notes`.
   - Optionally add trim start/end if present.
   - Rationale: Follows the same pattern as other steps (e.g., `_step_transcribe` stores paths).

#### Issue #4: cli.py --dry-run on transfer-transcripts doesn't prevent file transfer

**Description**: The `transfer-transcripts` subcommand accepts `--dry-run` but only uses it to skip writing corrections (line 197). The actual SCP file transfer still executes. A user running `--dry-run` would expect no files to be modified or transferred.

**Location**:
- File: `cli.py`
- Lines: `182-198`

**Offending Code**:
```python
elif args.command == "transfer-transcripts":
    from src.transfer.sync import TransferClient
    from src.config import LOCAL_TRANSCRIPTS
    client = TransferClient()
    remote_dir = "D:/MasterClass Video Backup/transcripts/"
    synced = client.sync_transcripts(remote_dir, LOCAL_TRANSCRIPTS, force=args.force)
    print(f"Synced {len(synced)} file(s)")
    if args.apply_corrections and synced:
        # ...
        if counts and not args.dry_run:
            fpath.write_text(new, encoding="utf-8")
```

**Recommended Solutions**:
1. **Guard the entire sync call with dry-run** (Preferred)
   - When `--dry-run`, list remote files via SSH but don't download. Print what _would_ be synced.
   - ```python
     if args.dry_run:
         # List what would sync without downloading
         ...
     else:
         synced = client.sync_transcripts(...)
     ```
   - Rationale: Consistent with `correct --dry-run` which previews without modifying.

2. **Rename to `--no-write-corrections`** (Alternative)
   - Make the flag name explicit about what it skips.
   - Trade-off: Less intuitive, but honest about behavior.
