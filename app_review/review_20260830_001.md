#### Issue #2: File handle opened but not closed in parent process

**Description**: `fh = open(log_file, "w")` is passed to `Popen` but the parent process never explicitly closes its reference. The parent exits almost immediately so the OS reclaims the fd, but explicit cleanup is better practice.

**Location**:
- File: `cli.py`
- Lines: `38`

**Offending Code**:
```python
fh = open(log_file, "w")  # noqa: SIM115
```

**Recommended Solutions**:
1. **Use `subprocess.STDOUT` for stderr and close the handle after Popen** (Preferred)
   - This is also the pattern shown in the spec. Open the file, pass it as `stdout`, use `stderr=subprocess.STDOUT`, then close the handle in the parent:
   ```python
   fh = open(log_file, "w")
   kwargs: dict = {"stdout": fh, "stderr": subprocess.STDOUT}
   # ... platform kwargs ...
   proc = subprocess.Popen(child_cmd, **kwargs)
   fh.close()
   ```

2. **Keep current approach, just close after Popen**
   - Add `fh.close()` after the `subprocess.Popen` call. The child inherits the fd at the OS level; closing the parent's Python file object doesn't affect the child.
