## Issues by Risk Tier

### ⚠️ HIGH RISK (Should Fix Before Merge)

#### Issue #1: Recorder pause detection uses hardcoded `document.querySelector('video')` instead of player handler

**Description**: The monitoring loop in `Recorder.record_one()` checks whether the video is paused by querying `document.querySelector('video')`. This bypasses the player handler's abstraction and may return wrong results for:
- Vimeo players (video is inside an iframe — `querySelector('video')` on the parent document returns `null`)
- Pages with multiple `<video>` elements (could match the wrong one)
- Future player types with non-standard DOM structures

The Recorder already has a `handler` reference with player-specific selectors, making this generic query unnecessary.

**Location**:
- File: `src/capture/recorder.py`
- Lines: `132-136`

**Offending Code**:
```python
is_paused = await cdp.js(
    "(() => { const v = document.querySelector('video');"
    " return v ? v.paused : false; })()"
)
```

**Recommended Solutions**:
1. **Add `is_paused()` to the PlayerHandler protocol and delegate** (Preferred)
   - Add `async def is_paused(self, cdp: CDPClient) -> bool: ...` to `PlayerHandler` in `src/players/base.py`
   - Each handler returns paused state using its player-specific selector
   - Rationale: Consistent with how `is_ended()`, `get_position()`, etc. work

2. **Use the detection result's element field**
   - Construct the JS query from `detection.element` rather than hardcoding `'video'`
   - Trade-off: Faster to implement, but doesn't handle iframe-based players (Vimeo)

### ⚡ MEDIUM RISK (Fix Soon)

#### Issue #3: YtDlpEngine is architecturally incompatible with Recorder's 10-step state machine

**Description**: The Recorder's `record_one()` workflow assumes screen capture: navigate to URL → detect player → fullscreen → monitor playback → stop. `YtDlpEngine` downloads directly via subprocess — it doesn't involve a browser tab or screen recording. Using `Recorder(YtDlpEngine())` would:
1. Navigate to a YouTube URL in Chrome
2. Detect the YouTube player
3. Enter fullscreen
4. Start a yt-dlp subprocess (which downloads independently)
5. Monitor in-browser playback position (unrelated to the download)

The plan states "The recorder should work with ANY combination of source + player + engine," but the Recorder's workflow semantically requires a screen-recording engine. The BatchOrchestrator has no separate code path for direct-download engines.

**Location**:
- File: `src/capture/recorder.py` (entire `record_one` method)
- File: `src/capture/batch.py` (lines 192, single code path)

**Recommended Solutions**:
1. **Add a `download_one()` method to Recorder for direct-download engines** (Preferred)
   - Skips steps 1-6 and 9 (navigation, player detection, fullscreen, monitoring)
   - Just calls `engine.set_url(url); engine.start(filename); engine.stop()`
   - BatchOrchestrator selects path based on `engine.name`

2. **Create a separate `Downloader` class alongside Recorder**
   - Simpler lifecycle: set_url → start → wait → return path
   - Trade-off: More classes, but clearer separation of concerns

3. **Accept this as a Phase 3 concern**
   - Document that YtDlpEngine is not meant for use with Recorder today
   - Trade-off: Defers work but the engine + protocol are in place

#### Issue #4: BatchOrchestrator._health_check accesses Preflight's private methods

**Description**: `BatchOrchestrator._health_check()` directly calls `self.preflight._ensure_chrome()` and `self.preflight._ensure_obs()` — private methods (prefixed with `_`). This couples the orchestrator to Preflight's internal implementation, breaking if those methods are renamed or refactored.

**Location**:
- File: `src/capture/batch.py`
- Lines: `210-216`

**Offending Code**:
```python
def _health_check(self) -> None:
    if not self.preflight:
        return
    chrome_ok = self.preflight._ensure_chrome()
    if not chrome_ok:
        log.warning("[health] Chrome CDP lost — attempting recovery")
    obs_ok = self.preflight._ensure_obs()
    if not obs_ok:
        log.warning("[health] OBS WebSocket lost — attempting recovery")
```

**Recommended Solutions**:
1. **Add a public `health_check()` method to Preflight** (Preferred)
   - `def health_check(self) -> tuple[bool, bool]` that returns `(chrome_ok, obs_ok)`
   - Rationale: Clean API boundary between the two classes
