### ⚠️ HIGH RISK (Should Fix Before Merge)

#### Issue #1: PowerShell file count can abort deploy under set -e

**Description**: The `powershell -Command "(Get-ChildItem ...)"` file count on line 88 is purely informational — it just prints how many Python files were deployed. However, running under `set -euo pipefail`, if PowerShell isn't available in the SSH session's PATH, the command name differs (`pwsh` vs `powershell`), or the command fails for any reason, the entire script exits immediately. At this point the deploy is already complete (SCP + uv sync succeeded), but the user loses the verification section and summary — and may think the deploy failed.

**Location**:
- File: `scripts/release.sh`
- Lines: `88-91`

**Offending Code**:
```bash
FILE_COUNT=$(ssh "$REMOTE" "cd $REMOTE_DIR; powershell -Command \"(Get-ChildItem -Path src -Recurse -Filter *.py).Count\"")
TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
echo "  Files deployed: $FILE_COUNT Python files"
echo "  Timestamp: $TIMESTAMP"
```

**Recommended Solutions**:
1. **Guard the informational command** (Preferred)
   - Wrap in an explicit check so failure is non-fatal:
     ```bash
     FILE_COUNT=$(ssh "$REMOTE" "cd $REMOTE_DIR; powershell -Command \"(Get-ChildItem -Path src -Recurse -Filter *.py).Count\"" 2>/dev/null) || FILE_COUNT="(unknown)"
     ```
   - Rationale: Informational output should never abort a successful deploy.

2. **Use TIMESTAMP unconditionally, make file count optional**
   - Move `TIMESTAMP=$(date ...)` before the SSH call and print it first, so at minimum the timestamp is always shown even if the file count fails.

### ⚡ MEDIUM RISK (Fix Soon)

#### Issue #2: Silent exit on --help verification failure

**Description**: The post-deploy `cli.py --help` verification on line 107 runs under `set -e` and redirects all output to `/dev/null`. If this SSH command fails (connection timeout, CLI import error, uv not synced), the script exits silently without printing any error message. The user sees no "fail" message and the summary section is never printed, making it unclear whether the deploy succeeded or failed.

**Location**:
- File: `scripts/release.sh`
- Lines: `107-108`

**Offending Code**:
```bash
ssh "$REMOTE" "cd $REMOTE_DIR; uv run cli.py --help" >/dev/null 2>&1
ok "CLI imports OK on obs-machine"
```

**Recommended Solutions**:
1. **Add explicit error handling** (Preferred)
   ```bash
   if ! ssh "$REMOTE" "cd $REMOTE_DIR; uv run cli.py --help" >/dev/null 2>&1; then
       warn "CLI --help check failed on obs-machine (may have import errors)"
   else
       ok "CLI imports OK on obs-machine"
   fi
   ```
   - Rationale: Verification failure after a successful deploy should warn, not abort — the files are already there. This also provides a diagnostic message.

2. **Use `|| true` to prevent abort**
   ```bash
   ssh "$REMOTE" "cd $REMOTE_DIR; uv run cli.py --help" >/dev/null 2>&1 || warn "CLI --help check failed"
   ```
