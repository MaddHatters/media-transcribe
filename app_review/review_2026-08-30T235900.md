### ⚡ MEDIUM RISK (Fix Soon)

#### Issue #1: `_health_check` couples to Preflight's private methods

**Description**: `Pipeline._health_check()` calls `self._preflight._ensure_chrome()` and `self._preflight._ensure_obs()`, which are underscored private methods on `Preflight`. If `Preflight` is refactored, these calls break silently. However, this is the same pattern used by `BatchOrchestrator._health_check()` in `src/capture/batch.py` (lines 210-218), so it's consistent with the existing codebase.

**Location**:
- File: `src/pipeline/runner.py`
- Lines: `51-59`

**Offending Code**:
```python
def _health_check(self) -> None:
    if not self._preflight:
        return
    chrome_ok = self._preflight._ensure_chrome()
    if not chrome_ok:
        log.warning("[health] Chrome CDP lost — attempting recovery")
    obs_ok = self._preflight._ensure_obs()
    if not obs_ok:
        log.warning("[health] OBS WebSocket lost — attempting recovery")
```

**Recommended Solutions**:
1. **Add a public `health_check()` method to `Preflight`** (Preferred)
   - Expose `ensure_chrome()` and `ensure_obs()` as public methods
   - Both `Pipeline` and `BatchOrchestrator` call the public methods
   - Rationale: Reduces coupling; one change fixes both callers

2. **Accept the current coupling** (Acceptable)
   - The pattern is already established in `BatchOrchestrator`
   - Preflight is an internal class unlikely to be refactored without updating callers
   - Trade-off: Consistent with codebase, but coupling to privates is fragile

#### Issue #3: Health check and breaks run after failed recordings

**Description**: In `Pipeline.run()`, the health check and break logic runs after every video regardless of success or failure. This means a failed recording still triggers recovery and a 5-25 minute break before the next attempt.

**Location**:
- File: `src/pipeline/runner.py`
- Lines: `85-89`

**Offending Code**:
```python
if "record" in active_steps and i < len(queue) - 1:
    self._health_check()
    if self._enable_breaks:
        from src.capture.batch import human_break
        await asyncio.to_thread(human_break, i + 1, len(queue))
```

**Recommended Solutions**:
1. **Keep current behavior** (Preferred)
   - If a recording failed because Chrome/OBS crashed, the health check recovers them before the next attempt
   - The break also helps avoid bot detection even after failures
   - This matches `BatchOrchestrator.run()` in `src/capture/batch.py` (lines 202-206)
   - Rationale: Recovery-first design is correct for unattended operation
