#### Issue #1: Unused `IS_WINDOWS` import in preflight.py

**Description**: After refactoring `_ensure_chrome()` and `_ensure_obs()` to delegate to `EnvironmentManager`, the `IS_WINDOWS` constant is no longer used anywhere in `preflight.py`. It was previously used in `if not IS_WINDOWS: return False` guards that were removed during the refactor.

**Location**:
- File: `src/capture/preflight.py`
- Lines: `19`

**Offending Code**:
```python
from src.config import (
    CDP_URL,
    OBS_HOST, OBS_PORT, OBS_PASSWORD,
    CRED_TARGET, IS_WINDOWS,
)
```

**Recommended Solutions**:
1. **Remove `IS_WINDOWS` from the import** (Preferred)
   - Change the import to: `from src.config import (CDP_URL, OBS_HOST, OBS_PORT, OBS_PASSWORD, CRED_TARGET)`
   - Rationale: Dead imports are linter violations and mislead readers into thinking the constant is used.

#### Issue #2: Polling timeout log message says "15s" but actual timeout is 16s

**Description**: Both `_setup_chrome()` and `_setup_obs()` poll 8 times with 2s sleep per iteration (8 × 2 = 16s), but the error log messages say "did not respond within 15s".

**Location**:
- File: `src/capture/environment.py`
- Lines: `170, 179` (Chrome) and `198, 208` (OBS)

**Offending Code**:
```python
for _ in range(8):
    time.sleep(2)
    # ...
log.error("Chrome CDP did not respond within 15s")
```

**Recommended Solutions**:
1. **Change loop to `range(7)` for 14s or update log message to "16s"**
   - Rationale: Minor cosmetic inaccuracy, no functional impact.

#### Issue #4: Redundant CDP health check on preflight→setup delegation path

**Description**: When `Preflight._ensure_chrome()` detects Chrome is down, it delegates to `EnvironmentManager._setup_chrome()`, which immediately checks CDP again (same URL, same timeout). The second check will also fail, adding ~5s of wasted time.

**Location**:
- File: `src/capture/preflight.py` lines `91-101` → `src/capture/environment.py` lines `156-161`

**Recommended Solutions**:
1. **Accept as-is** (Preferred)
   - The redundant check ensures `_setup_chrome()` works correctly when called standalone (e.g., from CLI `setup`). The 5s overhead is negligible for a setup flow.
